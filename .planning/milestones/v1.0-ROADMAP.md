# Milestone v1.0: Date Chooser MVP

**Status:** ✅ SHIPPED 2026-08-25
**Phases:** 1-4
**Total Plans:** 11

## Overview

A self-hosted, account-free meeting scheduler (Doodle/Rallly-style). An organizer creates a poll with candidate date/time slots, shares a participant link and a secret admin link, participants vote Yes/No/Maybe with an optional comment, everyone sees a results grid with tallies and a best-slot highlight, and the organizer can edit or delete the poll afterward. Ships as a single Docker image with SQLite on a mounted volume — no external services, no accounts.

Built as four end-to-end vertical slices, each independently demoable in the target deployment: Phase 1 got an organizer from nothing to a running Docker container that creates a poll and hands back links, with data surviving a restart. Phase 2 let a participant vote and revise later with no account. Phase 3 turned votes into the results grid everyone came for. Phase 4 closed the loop with organizer-side editing and deletion.

## Milestone Summary

**Key Decisions:**

- Go over Python for the backend — single static binary, minimal Docker image
- No accounts — access via unguessable participant/admin link tokens (crypto/rand, admin token independent of participant token)
- SQLite via `modernc.org/sqlite` (pure Go, no CGO) — embedded idempotent schema
- Server-rendered HTML (`html/template`) with small progressive-enhancement JS files, not a SPA
- Go 1.25 (bumped from planned 1.23) — `modernc.org/sqlite`'s transitive deps required it
- Participant identity via HttpOnly cookie (not login/name-matching) — anti-overwrite rule protects against name-collision data loss
- Tri-color Yes/No/Maybe pills (green/red/gray) and ✓/✗/? grid glyphs — both explicit user overrides of the UI researcher's more conservative single-token drafts
- Best-slot ranking: most Yes desc, fewest No tiebreak; ties highlight ALL tied slots
- Destructive-red escalated to real delete controls in Phase 4 (outline for per-response removal, solid fill for whole-poll deletion)

**Issues Resolved (found and fixed during the build, not carried forward as debt):**

- Date/time slot picker UX — replaced confusing `datetime-local` x2 inputs with separate date + time fields, then added an hour-dropdown + ±15min steppers
- Missing "Edit poll" navigation link — the `/edit` route worked but nothing in the UI linked to it; found via manual testing, fixed same session

**Issues Deferred (explicitly out of scope, tracked for a future milestone):**

- Notifications/email on new responses
- Timezone-aware slot display
- Calendar (.ics) export
- Poll "finalize" step that locks in the chosen slot

**Technical Debt Incurred:** None outstanding. All 12 browser-only verification items (double-submit guards, CSS rendering at mobile widths, clipboard behavior, sticky column, truncation) were manually confirmed by the user and closed in `.planning/WINDOWS.md`.
