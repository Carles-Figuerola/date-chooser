## Phase Goal (MVP user story)

**As a** poll participant who was sent a link, **I want to** open it with no account, mark Yes/No/Maybe (with an optional comment) for every proposed slot, and come back later to change my answer, **so that** the organizer can see my availability and I can keep it up to date — on phone or desktop.

> Derived directly from the ROADMAP Phase 2 `**Goal:**` line (not invented); all three story slots — actor, capability, outcome — are present in that goal.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| participant browser -> HTTP server | Untrusted form input (display_name, comment, per-slot answer) and the dc_participant cookie cross here |
| HTTP server -> SQLite | All persistence; parameterized SQL only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Spoofing | dc_participant cookie token (server.go) | high | mitigate | Cookie value generated by token.New() (crypto/rand, 128-bit) — never a guessable/sequential value; asserted by grep `token.New` in server.go and the crypto/rand negative gate below |
| T-02-02 | Info disclosure / Tampering | dc_participant cookie (server.go) | high | mitigate | Cookie set HttpOnly=true (no JS access) so an XSS payload cannot read or forge it; asserted by grep `HttpOnly` and the e2e test's Set-Cookie assertion |
| T-02-03 | Tampering / Broken access control | SaveResponse (participant.go) | high | mitigate | Upsert keyed strictly on (poll_id, cookie_token); a request with no matching cookie ALWAYS inserts a new participant — never merges by display_name. Proven by TestParticipant_NewCookieCreatesNewParticipant |
| T-02-05 | Injection (SQLi) | participant.go queries | high | mitigate | All queries parameterized (mirrors Phase 1 T-01-03); no string-built SQL |
| T-02-07 | Tampering | answer values (schema.sql + participant.go) | medium | mitigate | answer constrained by DB CHECK IN ('yes','no','maybe'); proven by TestResponse_AnswerEnumRejected |

Package legitimacy gate: not applicable — this phase adds no npm/pip/cargo installs (pure Go stdlib + the existing modernc.org/sqlite driver from Phase 1). No T-02-SC.

Cross-cutting negative gate (T-02-01): the web package must not import a non-cryptographic PRNG for token/cookie generation. Verified in <verification> below.
