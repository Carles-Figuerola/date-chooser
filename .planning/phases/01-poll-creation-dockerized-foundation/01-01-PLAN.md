<objective>
Build the Walking Skeleton for Date Chooser: the thinnest production-quality end-to-end slice that proves the whole stack. An organizer submits the create-poll form, the poll (title + one slot) is written to SQLite, two independent crypto-random tokens are generated, and the browser is redirected to a page showing the participant link and the secret admin link — all served by a single Docker image with data on a mounted /data volume that survives restarts.

Purpose: Establish and prove every architectural decision in SKELETON.md (Go single binary, net/http routing, modernc.org/sqlite, embedded idempotent schema, crypto/rand tokens, distroless Docker image, env-var config) so Plans 02-03 and Phases 2-4 expand horizontally on a verified backbone instead of discovering an architectural dead-end late.
Output: A buildable Go module, an end-to-end httptest that exercises form→DB→links, and a working multi-stage Dockerfile with a verified persistence check.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → HTTP handlers | Untrusted form input (title, description, organizer name, slot values) crosses into the app on POST /polls |
| link holder → poll data | Possession of a URL token is the entire authorization check; no accounts, no session |
| container → /data volume | The nonroot process must read/write the operator-provided SQLite volume |
| build → runtime image | Go module dependencies are baked into the shipped binary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information disclosure / Spoofing | internal/token/token.go participant + admin tokens | high | mitigate | Generate with `crypto/rand` only, 16 bytes (128-bit), base64url; negative gate asserts the non-crypto RNG import is absent (see Task 1 acceptance) |
| T-01-02 | Elevation of privilege | admin_token vs participant_token | high | mitigate | Two independent `token.New()` calls, stored in separate `polls` columns; admin token is NOT derived from participant token (CONTEXT decision); server_test asserts the two tokens differ |
| T-01-03 | Tampering | store.CreatePoll / PollByTokens SQL | high | mitigate | Parameterized placeholders only; no string concatenation of user input into SQL |
| T-01-04 | Denial of service | POST /polls request body size | medium | mitigate | Wrap the request body in `http.MaxBytesReader` (e.g. 1 MiB) before `ParseForm` (implemented/hardened in Plan 02); title/description length caps applied in Plan 02 |
| T-01-05 | Information disclosure | admin token in URL / access logs | low | accept | Inherent to the link-based access model (CONTEXT: no accounts, token entropy is the protection); TLS + log hygiene are the operator's responsibility (CONTEXT: HTTPS termination is operator-owned) |
| T-01-SC | Tampering (supply chain) | modernc.org/sqlite dependency | medium | mitigate | Single, widely-used pure-Go dependency; integrity pinned via `go.sum` checksums verified by the Go toolchain on build. Not an npm/pip/cargo install, so the package-legitimacy human checkpoint does not apply; version is pinned in go.mod |

Note: No `npm`/`pip`/`cargo` installs occur in this phase (Go modules only), so the `[ASSUMED]/[SUS]` install-legitimacy human checkpoint is not triggered. ASVS level 1, block-on `high`: T-01-01/02/03 are the high-severity items and are all mitigated with verifiable gates.
