<objective>
Improve the poll-creation form's client-side slot-picker UX: make the time-field controls the same height (SLOT-01), make the whole time input open the hour dropdown (SLOT-02), auto-fill a specific-time slot's end time to +1h without clobbering a manual edit (SLOT-03), and add a per-row Copy button that appends a pre-filled duplicate row (SLOT-04).

This is purely additive, client-side progressive-enhancement work on the already-shipped v1.0 create form. No new routes, no schema changes, no new templates — every change extends existing markup, CSS classes, and the existing create.js row/time-field machinery exactly as directed in 05-CONTEXT.md's "Existing Code Insights".

Purpose: reduce friction and re-entry errors when an organizer builds a multi-slot poll.
Output: modified style.css / create.js / create.html and a new Go test file (create_ux_test.go) that mechanically asserts the shipped source carries each behavior.

MVP note: MVP_MODE is on, but the ROADMAP Phase 5 **Goal** line is a plain outcome sentence, not an "As a / I want to / so that" user story. Per planner rules I do not invent a story; this is an unattended run so I surface it here and proceed. Run `/gsd mvp-phase 5` later if a formal user-story framing is wanted. Goal (verbatim): "An organizer creating a poll can pick times more easily (consistent-height controls, click-anywhere popup, auto-filled end time), duplicate a slot with one click instead of re-entering it, and gets a clear error instead of a silently-accepted duplicate slot."

Spec note: no UI-SPEC.md exists for this phase and none is required — 05-CONTEXT.md is the full, authoritative design spec (specless_probe_fallback is disabled project-wide; recorded as a deliberate choice). Visual/interaction decisions are already made in CONTEXT and are not gaps.
</objective>
