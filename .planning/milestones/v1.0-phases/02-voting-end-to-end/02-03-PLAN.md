## Phase Goal (MVP user story)

**As a** poll participant who was sent a link, **I want to** open it with no account, mark Yes/No/Maybe (with an optional comment) for every proposed slot, and come back later to change my answer, **so that** the organizer can see my availability and I can keep it up to date — on phone or desktop. (Derivation in 02-01-PLAN.md.)

<objective>
Turn the functional-but-plain voting form from the tracer + validation plans into the finished UI-SPEC surface: segmented Yes/No/Maybe pill groups with the tri-color selected states, native maxlength enforcement, the styled confirmation banner, a mobile-and-desktop single-column layout (VOTE-06), and a thin progressive-enhancement submit guard.

Purpose: The behavior is proven and validated; this plan delivers the scannable, tappable, responsive experience the UI-SPEC specifies without changing any server contract.
Output: Finished vote.html markup, extended style.css (pill group + banner + responsive), and vote.js — the pill selection works with CSS alone (no JS required), JS only adds the submit guard.
</objective>
