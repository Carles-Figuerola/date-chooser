# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope covered by this contract:** the organizer-facing poll-creation form and the post-creation
links-display page. No voting, results grid, or admin editing UI exists yet (Phases 2-4). Docker
packaging and SQLite persistence (OPS-01..04) have no UI surface and are out of scope for this
document.

**Stack basis:** Greenfield Go backend, server-rendered HTML (`html/template`) per
`01-CONTEXT.md` Claude's Discretion — no React/Next.js/Vite, so the shadcn initialization gate
does not apply (see Design System below).

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — not a React/Next.js/Vite stack; shadcn gate not applicable per CONTEXT.md decision to keep the Go binary dependency-light |
| Preset | not applicable |
| Component library | none — hand-rolled semantic HTML + a single static CSS file, no JS framework |
| Icon library | none — inline SVG for the one icon needed (copy-to-clipboard), no external icon dependency |
| Font | system font stack: `-apple-system, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` — zero external font requests, consistent with the self-hosted single-binary deployment goal |

Rationale: greenfield project, no existing `components.json`/Tailwind config/component
directories were found (confirmed via `ls`/`find`). This phase establishes the initial visual
system; later phases (2-4) inherit these tokens rather than re-deriving them.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline padding |
| sm | 8px | Gap between stacked slot rows, form field internal padding |
| md | 16px | Default gap between form fields, card internal padding |
| lg | 24px | Section padding (form container edge padding on desktop) |
| xl | 32px | Gap between major page sections (form vs. submit area) |
| 2xl | 48px | Space above/below the page title |
| 3xl | 64px | Not used in this phase (single-column form, no page-level rail) |

Exceptions:
- 44px minimum tap target height for all interactive controls (add-slot button, remove-slot
  button, copy-link button, all-day/date+time toggle) — mobile usability floor per VOTE-06's
  cross-device requirement applying equally to the creation form (POLL-02/03).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 600 (semibold) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

- Body (16px/400): form input text, description textarea, helper text, link display text.
- Label (14px/600): field labels ("Poll title", "Description", "Slots"), small meta text (slot
  counter "3 slots added").
- Heading (20px/600): in-page section headers ("Add slots", "Share this poll").
- Display (28px/600): page title ("Create a poll" on the creation form; the poll title itself on
  the links-display confirmation page).

Exactly 2 weights declared (400, 600) — no additional weights loaded, keeping the system font
stack dependency-free.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8FAFC` | Page background/canvas |
| Secondary (30%) | `#FFFFFF` | Form card surface, slot-row background, links-display card |
| Accent (10%) | `#2563EB` | See reserved list below |
| Destructive | `#DC2626` | See reserved list below |

Accent (`#2563EB`) reserved for:
- Primary CTA button ("Create poll")
- The participant link and admin link text/underline on the post-creation page
- Focus ring on all form inputs (`outline: 2px solid #2563EB`)
- Active/selected state of the all-day vs. date+time toggle

Destructive (`#DC2626`) reserved for:
- The "Remove slot" row action (icon + text) only — no other element in this phase uses red.

Neutral text/border colors (not part of the 60/30/10 split, standard UI grays): body text
`#1E293B`, secondary/helper text `#64748B`, borders `#E2E8F0`. These are declared here so the
executor doesn't invent ad hoc gray values.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Create poll" |
| Secondary action | "Add another slot" (adds a new slot row) |
| Empty state heading | Not applicable — the form always renders with one pre-filled blank slot row (POLL-02 requires ≥1 slot; the UI makes the true-zero-slot state unreachable rather than designing an empty-state message for it) |
| Empty state body | N/A (see above) |
| Error state — form validation | "Add at least one date or time option before creating your poll." (shown only if a race condition somehow allows zero rows; primary defense is disabling "Remove" on the last row) |
| Error state — field validation | "Check the highlighted fields and try again." (banner above the form, paired with inline per-field messages) |
| Error state — row-level | "End time must be after start time." (inline under the offending slot row, date+time mode only) |
| Error state — clipboard failure | "Couldn't copy automatically — select the link text above and copy it manually." |
| Destructive confirmation | "Remove slot": no modal confirmation — this is a pre-submit, instantly-reversible form edit (re-add restores it), so a blocking confirm dialog would be friction without safety benefit. Inline removal only. |
| Links page — admin link label | "Admin link (keep this secret)" |
| Links page — participant link label | "Participant link (share this with your group)" |
| Copy button label / confirmation | "Copy link" → on success, temporarily replaced with "Copied!" for 2 seconds |
| Slot counter | "1 slot added" / "N slots added" (singular/plural per zero-one-many below) |
| Many-slots hint (non-blocking) | "50+ slots can be hard for participants to scan — consider trimming the list." (shown once slot count exceeds ~50, per CONTEXT.md's soft-guidance decision; never blocks submission) |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5).

Applicable state considerations resolved: 13 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | poll creation form | ✅ covered | Form always renders with title placeholder text and exactly one pre-filled blank slot row; true zero-field state never shown to the user. |
| loading | poll creation form (submit) | 🧪 backstop | On submit, "Create poll" button disables and label changes to "Creating…" to block double-submit; executor must verify this actually prevents a second POST, not just visual state. |
| error | poll creation form | ✅ covered | Validation banner copy "Check the highlighted fields and try again." plus inline per-field messages (see Copywriting Contract). |
| partial | poll creation form | ✅ covered | Row with date filled but time missing (date+time mode) surfaces inline error only on submit attempt, not live-as-typed, to avoid nagging while typing. |
| long-text | poll creation form | ✅ covered | Title input capped at 200 chars (native `maxlength`), description textarea capped at 2000 chars, both wrap naturally — no truncation applied to what's stored or displayed. |
| empty | slot list | ✅ covered | Zero-slot state is made unreachable: "Remove" is disabled/hidden on the last remaining slot row (client-side), and the server independently rejects a zero-slot submission (POLL-02 minimum). |
| loading | slot list | dismissed | Slot rows are synchronous client-side form state at creation time — no async fetch exists to show a loading state for. |
| error | slot list | ✅ covered | Row-level error copy "End time must be after start time." inline under the offending row. |
| populated | slot list | ✅ covered | Rows stack vertically with 8px (sm token) gaps; each row shows the date/time input(s) plus a "Remove" action. |
| partial | slot list | ✅ covered | See "partial / poll creation form" row above — same resolution applies at the row level. |
| overflow | slot list | ✅ covered | No fixed-height scroll container — list grows with the page (simplest, most mobile-friendly). Past ~50 rows, non-blocking hint copy appears (see Copywriting Contract). |
| zero-one-many | slot list | ✅ covered | Counter text reads "1 slot added" (singular) vs. "N slots added" (plural), placed near the "Add another slot" button. |
| long-text | slot list | dismissed | Slot rows are structured date/time inputs, not free text — no long-text case exists. |
| loading / error | copy-to-clipboard controls | ✅ covered | Success shows "Copied!" for 2s; failure (e.g. clipboard permission denied) falls back to manual-select copy with the stated error copy. |
| overflow / long-text | links-display page (participant + admin link) | 🧪 backstop | Long token URLs must wrap via `word-break: break-all` inside a bordered box on narrow (mobile) viewports, never causing horizontal page scroll; executor must verify at a ~360px viewport width, not just declare the CSS rule. |
